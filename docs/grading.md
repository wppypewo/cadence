# 打字題的批改

## 立場：重音算數

`écrire` 打成 `ecrire` 就是錯的。

這不是嚴格主義。法文的變音符號會改變語意（`ou`／`où`、`a`／`à`、`sur`／`sûr`），考卷上會扣分，而且是那種每次都告訴自己「我其實知道」然後每次都再錯一遍的類型。放水的複習工具會讓這個錯誤永遠留著。

大小寫則不算錯。法文的句首大寫與詞典形大寫是排版問題，不是拼字問題。

## 五種判定

`grade(input, accepted)` 回傳 `reason`，`src/api.mjs` 依它換算 FSRS 評分：

| reason | 判定 | 算對嗎 | 評分 |
|---|---|---|---|
| `exact` | 正規化後完全相同 | 對 | 3（Good） |
| `case` | 只有大小寫不同 | 對 | 2（Hard） |
| `accent` | 去掉所有變音符號後相同 | 錯 | 1（Again） |
| `wrong` | 以上皆非 | 錯 | 1（Again） |
| `empty` | 沒作答 | 錯 | 1（Again） |

判定有順序：先試完全相同，再試大小寫，最後才試去重音。所以「大小寫和重音都不同」會落在 `accent`，算錯。

`accent` 給 Again 而不是 Hard，是「重音算數」這個立場的直接後果——它與拼錯受一樣的懲罰，卡片退回重來。但畫面上與統計裡它是分開的一類，因為改進方法不一樣：拼錯要重背，漏重音只要把符號刻進肌肉記憶。統計頁的「錯在哪裡」面板會直接算出漏重音佔所有打字錯誤的比例。

## 正規化

比對之前做四件事：

1. `normalize('NFC')` — `é` 有兩種 Unicode 表示法（單一碼位，或 `e` 加組合重音），看起來一樣但不相等。輸入法不同就會產生不同的那一種。
2. 撇號統一成 `’`（U+2019）— 法文排版用的是這個，但鍵盤打出來的通常是 `'`。`l'homme` 與 `l’homme` 應該算同一個。
3. 收掉多餘空白。
4. 前後空白去掉。

「去重音」另外做，用 `NFD` 拆開再刪掉所有 `\p{Diacritic}`，並額外處理 `œ→oe`、`æ→ae`——那兩個是連字不是重音，`NFD` 拆不開。

## 多個可接受答案

有些卡不只一個正確答案（同義詞、變位的異體）。`accept` 欄位收所有可接受的寫法，第一個是標準答案；比對時逐一試，回傳的 `matched` 說明是哪一個對上的。

答錯時另外算兩件事給畫面用：`diffChars()` 以正確答案為骨架標出哪幾個字元不同（單純等長對齊，答案通常只差一兩個字元，完整編輯距離在這裡沒有收益），`missingAccents()` 列出漏掉的變音字母。

## 前後端共用

`src/engine/grade.mjs` 同時被 Node 與瀏覽器 import。批改在前端做是為了即時回饋（不等網路來回），在後端做是為了寫進 `reviews.jsonl` 的評分可信。共用一份實作，兩邊不可能給出不同答案。
